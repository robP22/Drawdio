# UI Audit — 2026-08-29

Six deep analyses of the Drawdio editor UI: rendering, layout, interaction,
threading/sync, dead code, and accessibility. Ground truth: current
`Source/UI/`, `Source/PluginEditor.*`, `Source/PedalboardGrid.*`, `Source/GridLayout.h`,
JUCE 8.0.4. Items marked (FIXED) were corrected in this pass; the rest are
findings, known limitations, or deferred work.

## 1. Rendering & performance

- **(FIXED) Overlay staleness on large strokes** — `PixelCanvasComponent.cpp:576-578`:
  `updateOverlayPixel` capped the pending overlay cell list at 4096 by *clearing*
  it, permanently dropping the unflushed cells: `pixels[]` (state) and
  `m_pixelOverlay` (render) diverged until the next full rebuild (resize/clear/
  fill/preset load). Reachable with a large brush + fast drag (one mouse event
  can queue tens of thousands of cells). Now the cap sets `m_overlayDirty = true`
  instead, so the next `paint()` performs a full overlay rebuild (already the
  path for undo/clear/fill); `flushPendingOverlay`'s dirty-flag early return and
  `paint()`'s rebuild check were already consistent with this.
- Canvas redraws the 1 MB texture + overlay on every stroke event; per-cell
  `repaint()` regions coalesce within an event but each event repaints the
  canvas area. Acceptable; a dirty-rect overlay is the next lever.
- Palette (12 blobs, ~9 gradient fills each) and pedals are
  `setBufferedToImage(true)`-cached; ArcButton hover/press repaints are cheap;
  grain and noise textures are generated once (static).
- The 20 Hz timer path is repaint-gated end-to-end
  (`EditorSyncController::needsRepaint`, `MixerStrip::tick`, automation display).

## 2. Layout & geometry

- `PedalboardLayout`, the canvas square, the knob schema, and the cable
  channels are consistent at design resolution (1400 x 900).
- **(FIXED) Negative automation width** — `BottomControlBar.cpp:124-126`: the
  automation display width `stripStartX - autoX - pad` goes negative below
  roughly 577 px of bar width (at design height), which yields invalid JUCE
  bounds (debug assert, broken paint). Clamped with `juce::jmax(0, ...)`.
  `usableH = 0.833 * h` is always positive, so no other clamp is needed.
- Palette/canvas alignment is driven by sprite alpha-ratio scans
  (`PluginEditor.cpp:174-203`, `EditorLayout.h`) — correct but sprite-coupled;
  extreme aspect ratios should be smoke-tested when sprites change.

## 3. Interaction & state

- Canvas state machine (stroke/undo/redo/fill/rebound) is sound: undo byte
  budget (32 levels / 8 MB), exclusive palette toggles, rebound fold math,
  flood fill bounded to 65 536 cells.
- `ManualRoutingController` verified: new-cable / grab / reconnect / conflict /
  DAW-in-out semantics are correct, including the drag-onto-empty delete path
  and self/double-connection rejection.
- ArcButton hit-testing is path-based; press-cancel on drag-out; click
  activation requires the release inside the path.

## 4. Threading & sync

- UI state is driven by a 20 Hz timer → `EditorSyncController::tick`; config
  consume, knob/automation sync, and routing refresh are change-gated.
- `CanvasMessageQueue` is a correct SPSC ring (no extra flags); the canvas
  snapshot → compiler → UI-consume pipeline has no lost-update paths
  (verify: `consumeCompiledResultIfAvailable` runs before the UI notification
  gate).
- Image import dithering (256 x 256 Floyd-Steinberg) and preset I/O run on the
  UI thread inside file-chooser callbacks: tens of ms worst case, acceptable.

## 5. Dead code & API hygiene

- **(FIXED) `m_changedCellCount`** — `PixelCanvasComponent.h:150` + five write
  sites, zero reads (legacy compile-gating counter). Removed.
- Theme interface (`IThemeProvider`/`ThemeManager`) intentionally kept as-is:
  ten methods (`pedalSkin`, `canvasSurface`, LED colours, accent colours,
  palette selection/hover colours) have no consumers — components hardcode
  those values. Kept as a zero-cost future theming seam; revisit if the
  interface ever grows.
- `ArcButton::setArc` 5-arg overload is used (clear button), not dead.

## 6. Accessibility & polish

- ArcButtons: keyboard focusable (space/return activate, focus grabbed on
  click) — **(FIXED) now with a visible focus ring** (`ArcButton.cpp` paint,
  white 55% stroke over the arc path when focused; `focusGained`/`focusLost`
  repaint).
- **(FIXED) Tooltips** — none of the icon-only palette buttons displayed help:
  `setTooltip` exists only on `SettableTooltipClient` (JUCE 8), and no
  `TooltipWindow` existed. Added a `juce::TooltipWindow` to
  `DrawdioProcessorEditor`, `ArcButton` now inherits `SettableTooltipClient`,
  and the seven palette buttons set the same text as their accessibility names.
- Deferred (user decision): canvas keyboard drawing (arrows), Ctrl+Z/Y,
  knob fine-adjust keys.
- Fixed 9 px fonts in `MixerStrip`/`BottomControlBar` labels render small at
  high zoom; scale with component height when the visual pass returns.

## Verification

- Debug + Release plugin builds clean; `drawdio_tests` 29/29 cases green
  (4 762 874 assertions).
- Manual checks pending: fast large-brush strokes (overlay freshness), narrow
  window (automation bar), tooltips and tab-focus ring on palette buttons.

## Positioning system unification (same day, second pass)

Anomalies found across the positioning system and their resolutions. Full
conventions: `docs/positioning.md`.

| # | Anomaly | Resolution |
|---|---|---|
| A1 | Fixed-px caps inside ratio systems: bottom-bar caps (50/70/18 px), `JackHitMap` radius 24 px, DAW jack height 14 px | `GridLayout::scaledCap` + `scaleFromHeight`; jack radius now `clamp(12, min(w,h)·24/770, 24)` refreshed with the grid; DAW jack y via `CableJackHeightRatio` (exact at design size) |
| A2 | `JackHitMap::kRadius` static → hit zones didn't shrink with the window (overlap risk below ~500 px width) | Radius is now a member computed in `refresh()`; `ManualRoutingController` reads `m_jackMap.radius()` |
| A3 | Sprite-scan coupling: the editor held the palette sprite ratios and pushed three pixel values into the palette + one into the canvas | `ColorPalette` scans its own `ColorPaletteBody` sprite in its constructor; the editor keeps only the pedal sprite ratios; `setImageBottomShift`/`setContentCenterOffset`/`setCanvasTopOffset` replaced by semantic `setPedalBottomRatio(ratio)` and `setContentTop(ratio, columnHeightPx)`. Palette shift = `roundToInt(columnH·ratio) − roundToInt(paletteH·bottomR)` with `columnH = getY() + height` — proven equal to the old `pedalH·pedalBotR − paletteH·paletteBotR` (both areas share the topArea height) |
| A4 | Canvas dual anchor mode (pixel offset vs centered fallback) | Kept the fallback but keyed on the ratio/column being unset; the primary path is now fully internal to the canvas |
| A5 | Fixed 9 px fonts in `MixerStrip`/`BottomControlBar` | `clamp(7, h·0.09, 12)` (9 px at design size) |
| A6 | Undocumented tune constants | One-line rationales on `KnobCenterYShiftRatio`, `CanvasCenterX/YShiftRatio`, `VerticalGroupOffsetRatio` in `GridLayout.h` |
| A7 | Dead constants `PaletteButtonGapRatio`, `ButtonSquareSizeRatio` | Removed (zero usages) |
| A8 | Cable px constants (`CableLaneSpacingPx`, `CableWaypointCurvePx`, `CableArcLiftPx`) | Left as-is — the cable agent's domain; flagged only |

Design-size arithmetic verified identical (see the equivalence notes above);
Debug + Release builds clean; tests 29/29.
